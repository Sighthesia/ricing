# 动效与性能：先分类，再动手

这个域收的是七类"看着像动画参数不对、其实是提交路径不对"的故障：逐帧跨昂贵边界、主副两层各走各的时钟、内容比宿主先准备好、一次性冷初始化、启动各阶段互相踩、跟随器被逐帧重设、退出帧残留状态。总则只有一句：**先确定是什么东西每帧在付代价，再决定改哪个量**——缓动参数只改观感曲线，改不了提交节奏，也替代不了读不到的完成信号和一次性冷成本。

## 先看这里

按下面五步依次排他，**命中一条就停**，不要先读源码再猜。

1. **一次性还是持续性？** 判定依据：第二次触发是否还卡。首次大搜索/首次打开慢、再试就顺 → 冷路径（一次性）；每次都卡且与内容多少无关 → 逐帧提交。开机的"分几段卡"天然是一次性，直接按启动时序读。
2. **持续性的话，被动画驱动的量是否每帧跨过昂贵边界？** 判定依据：顺着"这个动画属性最终喂给了谁"往上找，只要落到顶层窗口的 `implicitWidth/Height`、compositor 的 input/visible/blur region、跨进程或跨 surface 的提交、或每帧重建的 model/对象图，就是它。指纹是"单帧工作量很小却周期性掉帧"，且同工程里有个结构相似却顺滑的兄弟。
3. **还是主层每帧而副层异步提交？** 判定依据：只在运动中出问题、静止时完全正常，且方向不对称（收缩溢出、展开留空）——两层在各自的时钟上采样，副层永远慢半拍。
4. **还是内容比宿主先准备好？** 判定依据：内容是"被宿主露出来"而不是"随宿主长出来"，硬切线沿着宿主的矩形走、切掉圆角或耳朵。此时调 inset、加遮罩、去缩放都只是换一个症状。
5. **剩下两类看错误发生的时刻。** 判定依据：只在"切换瞬间"错（残影、旧字消失、桌面闪一下）→ 退出帧状态；只在"标记移动"时错（拖尾被截断、冻结、跳变）→ 跟随器与采样方式。

## 按症状路由

| 症状 / 任务 | 类别 | 读这个 | 一句话修复方向 |
|---|---|---|---|
| 展开/收起/生长动画掉帧，但单帧工作量看起来很小；同工程有个结构相似却顺滑的表面 | 逐帧跨昂贵边界 | `references/surface-resize.md` | 把昂贵的外边界（窗口尺寸 / region / model）钉成常量，只动画内部内容并 clip；动画热路径不许分配。 |
| 模糊、阴影或遮罩在收缩时溢出轮廓、在展开时留出空隙，静止时又完全正常 | 主副双层时钟 | `references/async-layer.md` | 副层值保持连续不阶跃，只对移动边、只在出错方向加一个随速度变化且两端自归零的 lead。 |
| 表面生长时内容被硬切像剪刀；调 inset、加遮罩、去缩放都只是把一个症状换成另一个 | reveal 早于宿主 | `references/reveal-before-clip.md` | 用宿主的 reveal 进度驱动内容可见性并从可见边进入；矩形 clip 只当 1px 兜底。 |
| 首次大搜索 / 首次打开卡一下，第二次明显流畅 | 一次性冷初始化 | `references/cold-prewarm.md` | 隐藏预热一小批代表性子树把冷成本提前，搜索语义与列表结构一点不动。 |
| 开机分几段卡、wallpaper reveal 或 bar 展开被打断，而不是一次到位 | 启动阶段调度 | `references/startup-reveal.md` | 先埋点看 event-loop gap，用真实完成信号（不是猜测延时、不是 `Timer`）做 gate。 |
| 指示条拖尾被截断、冻结、跳变，或被逐帧重设的 `Behavior` 吞掉 | 跟随器与采样 | `references/trail-wake.md` | 目标在动就换 16ms 跟随器按比例收口；别用每帧 reset 的 `Behavior`，也别用阶梯时钟量它的运动。 |
| 长标题切换时旧字消失而不是下落（标题残影）；桌面标题在 workspace 间切换时闪一下 | 退出帧状态 | `references/marquee-exit.md` | 按可见区而不是前缀切 ghost，未揭示的字直接消失；桌面插入用 120ms hold 合并掉。 |

## 通用法则

七份来源里反复踩的是同样几条硬约束，不要按文件各记一遍：

- **动画不驱动昂贵边界。** 顶层窗口尺寸、compositor region/mask/blur、跨进程提交、每帧重建的大对象图都不是逐帧安全的量。外边界钉住、内部内容动画 + clip，并让 reservation/exclusiveZone 单独钉住，否则布局跟着回流。
- **副层的值必须连续，不许阶跃。** 把异步层直接设成"目标值"只是把抖动换成 pop/消失；任何 lead / inset / offset 在静止和运动起点都必须为零，只作用于移动边。
- **一次性冷路径提前预热，不要重写架构。** "只有第一次卡"是冷初始化证据：预热代表性子集、并行独立阶段、把冷路径推迟到第一帧之后走显式 gate。改搜索/列表架构是效果没变好之后的下一步，不是第一步。
- **两条独立时钟的问题不要用缓动参数去修。** spring / damping / duration 同步不了主层与副层，替代不了 readiness signal；同理，"缺一个完成信号"不能修成"加一个 Timer"。
- **启动阶段任何改动后要重新核对所有计时预算。** 拉长一个阶段会静默打破所有按旧长度校准的 timeout/watchdog——grep 一遍并按新长度显式覆盖，否则健康登录也会走降级路径。

## 交叉指引

- 本域每条修复都有同一个假信号：动完手，跑一次，看着好了。凡是"看起来好了"的结论都要走 `regression-proof` 的纪律——证明回退修复会让验证变红，否则那条验证是装饰；一次干净的现象观察不算证据。
- 启动相关改动（`startup-reveal`）还要看 `quickshell-platform-traps` 里的 Variants delegate 陷阱：静态检查通过、表面却根本没上屏，是这类改动的经典空验证。
- 三条共同的观测前提，不然读多少源码都会继续猜错：量 event-loop gap 找一次性阻塞，用 wall clock 采样判断标识自身的运动，用真实 reload 复现启动路径。
